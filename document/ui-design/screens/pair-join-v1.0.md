| 字段 | 值 |
|---|---|
| 屏幕 slug | pair-join |

---

## 1. 目的

配偶 B 输入 A 给的 6 位邀请码,加入家庭。

---

## 2. 触发 / 入口

- 从 pair-home 点击"加入家庭"卡片

---

## 3. 布局描述

```
┌────────────────────────────────────┐
│  ←                                │
│                                      │
│         输入邀请码                    │  ← 22px title
│                                      │
│   问配偶要 6 位邀请码                  │  ← 15px secondary
│                                      │
│   ╭──╮╭──╮╭──╮╭──╮╭──╮╭──╮         │  ← 6 个输入格
│   │ 4││ 8││ 2│ │  │  │  │         │     56×72px
│   ╰──╯╰──╯╰──╯╰──╯╰──╯╰──╯         │     当前格赤陶描边
│                                      │     已填主色文字
│                                      │     未填 tertiary
│                                      │
│   (隐藏的 TextInput,6 个格子共享焦点)  │
│                                      │
│   ⚠ 邀请码无效,请检查后重试           │  ← 错误提示(失败时)
│                                      │
│                                      │
│   [       确认加入       ]           │  ← 主按钮
│                                      │
│   还没有邀请码? 让配偶打开 app       │  ← 帮助文案
│   在家庭页生成一个                   │
│                                      │
└────────────────────────────────────┘
```

- **顶部**:← 返回(回 pair-home)
- **6 个输入格**:与 InviteCodeDisplay 风格一致,圆角 12,56×72px,**当前聚焦的格有 2px `--color-primary` 描边**
- **键盘**:自动唤起 numeric keyboard
- **自动跳转焦点**:填完第 N 位自动 focus 第 N+1 位;填完第 6 位自动调 accept_invite RPC
- **错误提示**:格子下方红字 13px,仅在失败时显示
- **确认按钮**:full-width primary,文案`确认加入`;**只在 6 位全填后 enabled**
- **帮助文案**:底部 13px secondary,纯文本

---

## 4. 组件分解

| 组件 | 来自 | 说明 |
|---|---|---|
| `Header` | Tamagui | ← 返回 + 标题 |
| `OtpInput` | 自定义 | 6 位数字输入器(国内常用"格子输入"模式) |
| `Button` | Tamagui | "确认加入" primary |
| `Text`(帮助) | Tamagui | 13px secondary |

---

## 5. 状态

| 状态 | 触发 | 视觉 |
|---|---|---|
| **empty** | 初始 | 6 个空格,tip 在第 1 格 |
| **partial** | 填了 1-5 位 | 已填主色,未填 tertiary,主按钮 disabled |
| **complete** | 填完 6 位 | 全部主色,主按钮 enabled,自动调 RPC |
| **submitting** | RPC 调用中 | 主按钮变 spinner + 文案"加入中..." |
| **invalid** | RPC 返回 invalid | 6 格轻微 shake(200ms)+ 红字"邀请码无效,请检查" + 清空输入 + 主按钮变回 disabled |
| **expired** | RPC 返回 expired | 红字"邀请码已过期,请向配偶索取新码" + 不清空(用户可改) |
| **already-used** | RPC 返回 used | 红字"这个邀请码已被使用" |
| **family-full** | 2 人上限 | 红字"这个家庭已经有 2 个成员了" |
| **network-error** | 网络断 | 顶部红色 banner"网络异常";输入保留,可稍后重试 |
| **success** | RPC 成功 | 整屏淡出 + 0.5s 后跳到主 App(显示"✨ 已加入 [家庭]!") |

---

## 6. 内容

- **页面标题**:`输入邀请码`
- **副标题**:`问配偶要 6 位邀请码`
- **错误文案**:
  - `邀请码无效,请检查后重试`
  - `邀请码已过期,请向配偶索取新码`
  - `这个邀请码已被使用`
  - `这个家庭已经有 2 个成员了`
  - `网络异常,请稍后重试`
- **主按钮**:`确认加入` / 提交中 `加入中...`
- **帮助文案**:`还没有邀请码?让配偶打开 app 在家庭页生成一个`
- **成功提示**:`已加入!正在为你跳转到主页...`

---

## 7. 可访问性

- 6 个输入格共一个 `accessibilityRole="text"`,整体 label `6 位邀请码输入框,已填 3 位`
- 错误提示 `accessibilityLiveRegion="assertive"`,失败时立即读出
- 主按钮在 disabled 时 `accessibilityState={{disabled: true}}`

---

## 8. 响应式行为

- 小屏 `≤ 360px`:输入格缩为 48×60px,字号 32px
- 键盘弹起时,页面整体上移,确保错误提示 + 主按钮可见

---

## 9. 出站导航

| 触发 | 跳转 |
|---|---|
| ← 返回 | pair-home |
| RPC 成功 | 主 App(任务 Tab) |
| 网络断 | 留在本页 |

---

## 10. 微文案规范

- 错误信息用"邀请码"而非"code",保持中文一致性
- 错误说明告诉用户**下一步做什么**(检查 / 索取新码),不只是失败事实
- "确认加入" 比 "提交" 更具体,降低认知负担
- 帮助文案让用户在没有配偶邀请码时也有出口
