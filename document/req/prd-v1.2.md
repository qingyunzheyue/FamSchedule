## 1. 背景与问题陈述

### 1.1 现状与痛点
- 夫妻(尤其有孩子后)每天需要协调大量事务:孩子照顾、健康习惯、个人工作、家庭行政(账单/保险/手续)。
- 现有工具割裂:**日历 app** 擅长记录但缺乏任务/打卡机制;**习惯打卡 app** 支持打卡但缺乏多人协作;**待办 app** 能协作但社交属性过重、隐私模型不匹配"家庭内部使用"。
- 微信/口头沟通容易被淹没,事后追溯困难。
- 缺乏一个**轻量、隐私友好、为家庭内部设计**的统一工具,能同时覆盖「日程 + 打卡 + 共享」三个动作。

### 1.2 机会
- 国内 Android 端家庭场景缺乏垂直产品。
- 借助 Expo + 国内推送通道,可以低成本快速验证。
- 先在自家小范围试用,验证核心循环是否管用。

### 1.3 一句话定义
> FamSchedule 是一个**面向家庭内部**(目前为夫妻两人)的轻量日程与打卡管理 Android 应用,核心闭环是「创建任务 → 按时提醒 → 一键打卡 → 共同追踪」。

## 2. 目标与非目标

### 2.1 目标(Goals)
- **G1**:提供简单直观的家庭事务管理工具,覆盖任务创建、提醒、打卡、共享四大核心动作。
- **G2**:支持一次性任务与周期任务(每日/每周/每月/自定义)。
- **G3**:在指定时间点推送提醒,降低遗忘率。
- **G4**:支持夫妻双方共同查看与执行任务,默认隐私可控。
- **G5**:**MVP 成功标准(M2 观察期,2-3 个月)**
  - 活跃度:30 天周期内,夫妻双方各自打开 app **≥ 15-20 天**
  - 任务量:每个活跃家庭每周执行任务数 **≥ 5 个**
  - 观察期:**2-3 个月**

### 2.2 非目标(Non-Goals)
- ❌ 不做社交化(朋友圈、社区、关注/粉丝)。
- ❌ 不做电商、购物清单、记账等周边功能。
- ❌ MVP 不做孩子账号、长辈账号(仅支持夫妻两人)。
- ❌ MVP 不做跨家庭协作、邀请码通用化。
- ❌ MVP 不做复杂统计报表、数据导出。
- ❌ MVP 不上 Google Play / 国内安卓市场,通过 APK 直接安装(家庭试用)。

## 3. 目标用户 / Persona

### 3.1 主要用户
**P1 — 夫妻(发起方)**
- 角色:产品的「建设者」也是首批用户。
- 特征:中等收入,Android 用户,智能手机熟练,有共同事务需要协调,至少一方有孩子。
- 痛点:事务繁多、容易遗忘、对方不清楚进度,事后靠微信回忆成本高。

**P2 — 配偶**
- 角色:被邀请加入家庭。
- 特征:同样有 Android 手机,愿意配合使用。
- 期望:不想用太复杂的工具,点一下能打卡、能收到提醒就够。

> 📌 **v1.1 补充**:**MVP 不做真实账号体系**,用户身份采用「**匿名设备 ID**」(详见 US-013);家庭关系通过**邀请码配对**(详见 US-012)。这避免了手机号/邮箱注册,适合家庭内部小范围使用。

### 3.2 用户规模
- 首发:MVP 仅服务**一个家庭**(自家),不开放注册。
- 后续:产品验证后再考虑多家庭扩展。

### 4.2 用户故事(User Stories)

#### M1 — 任务管理

**US-001 创建任务**
- **As a** 家庭成员
- **I want** 创建一个任务(标题、时间、指派人、可选周期)
- **So that** 我能记录需要做的事,到点不被遗忘
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 必填项:标题、时间、指派人
  - 可选项:周期(每日/每周/每月/自定义)、备注、是否共享
  - 任务默认私有,创建者可加共同执行人

**US-002 查看任务列表**
- **As a** 家庭成员
- **I want** 查看我的任务列表(今天/本周/全部)
- **So that** 我能清晰看到自己该做什么
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 列表支持「今天」「本周」「全部」视图切换
  - 显示任务状态(待办 / 已完成 / 已过期)
  - 可按指派人筛选

**US-003 编辑/删除任务**
- **As a** 任务创建者
- **I want** 编辑或删除我创建的任务
- **So that** 我能修正错误或取消不需要的任务
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 仅任务创建者可编辑/删除(共同执行人不能改)
  - 编辑/删除操作有二次确认
  - 周期任务可单独删除某一实例而不影响后续

#### M2 — 周期任务与打卡

**US-004 设置周期任务**
- **As a** 任务创建者
- **I want** 把任务设置为每日/每周/每月重复
- **So that** 习惯类任务不用每次都重新创建
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 支持预设:每日、每周(选星期几)、每月(选几号)
  - 周期设置后自动展开为对应实例
  - 周期结束时间(可选):如不填则长期有效

**US-005 一键打卡**(v1.1 修订)
- **As a** 任务指派人
- **I want** 在 app 内一键点击完成任务打卡
- **So that** 我能快速标记完成,不被流程打断
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - **每个任务都有独立的打卡入口**(不是全局一键,而是按任务逐个)
  - 任务**列表项**上有「打卡」按钮,直接点击即可
  - 任务**详情页**有「打卡」按钮
  - 任意入口点击后状态立刻变为「已完成」,所有入口 UI 实时同步更新
  - 打卡时间被记录,可事后查看
  - 共同执行人各自的 app 都能打卡,任一方完成即标完成
  - 已打卡的任务支持「撤销打卡」(在打卡后 5 分钟内)
- > 📌 v1.1 修订:明确「**每个任务独立打卡入口**」,列表项和详情页都能直接打卡。

**US-006 漏打卡补救(补卡)**
- **As a** 任务指派人
- **I want** 漏打卡后能补卡
- **So that** 不会因为一时忘记就破坏连续记录
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 周期任务支持补打卡过去某一实例
  - 补卡有截止时间(默认当天结束前可补前一天,**截止时间在 US-017 设置中可调整**)
  - 补卡操作在任务历史中留痕,标注「补卡」

**US-014 过期任务标记**(v1.1 新增)
- **As a** 用户
- **I want** 看到过期未完成的任务被明确标记
- **So that** 我能识别需要补做的事
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 任务列表上过期任务显示「已过期」红色标签(**永久**,与启动 banner 范围无关)
  - 任务详情页顶部有「此任务已过期 X 小时」banner
  - 过期任务仍可正常打卡或补卡(US-005、US-006)
  - 过期判断标准:任务预定时间已过且未被标记完成

**US-015 启动时过期任务提示**(v1.1 新增,v1.2 修订)
- **As a** 用户
- **I want** 打开 app 时被告知有任务过期
- **So that** 我能优先处理
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - app 启动时根据「过期提示窗口」设置检查过期任务
  - 默认窗口为「**今日 + 昨日**」
  - 用户可在 US-017 设置中调整窗口:今+昨(默认)/ 本周(周一~今)/ 全部 / 关闭
  - 顶部显示 banner「你有 N 个任务过期未完成,点击查看」
  - 点击 banner 跳转到过期任务列表
  - 用户处理(打卡/补卡)后 banner 自动消失
- > 📌 v1.2 修订:banner 时间窗由硬编码改为**可配置**,默认仍是「今日 + 昨日」。

#### M3 — 提醒

**US-007 到点精确推送**
- **As a** 任务指派人
- **I want** 任务到点时收到推送提醒
- **So that** 我不会忘记
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 任务时间到时通过系统通知推送
  - 通知内容包含任务标题
  - 点击通知直接打开 app 并定位到该任务详情
  - 推送通道:Expo Push(覆盖国内 Android)

**US-008 早/晚汇总**
- **As a** 家庭成员
- **I want** 每天早上和晚上各收到一次汇总通知
- **So that** 我能概览今天任务进度
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 早汇总(默认 08:00,**在 US-017 设置中可调整**):「今日任务」,列出今天所有任务
  - 晚汇总(默认 20:00,**在 US-017 设置中可调整**):「未完成提醒」,列出未打卡任务
  - 推送时间在设置中可调整

**US-016 后台推送优化引导**(v1.1 新增)
- **As a** 首次启动的用户
- **I want** 收到引导把 app 加入电池白名单/自启动
- **So that** 推送通知能可靠到达,不会因为系统杀掉 app 而丢失
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 首次启动时检测推送通道是否被系统限制(token 获取失败)
  - 若被限制,弹出引导卡片
  - 针对不同厂商(小米/华为/OPPO/vivo/三星)提供对应的「加入白名单/自启动」路径指引(图文)
  - 用户可选择「跳过」,但每次启动仍会温和提示(最多每天一次)
  - **US-017 设置中提供「重新检测」入口**

#### M4 — 共享与权限

**US-009 添加共同执行人**
- **As a** 任务创建者
- **I want** 给任务添加配偶为共同执行人
- **So that** 双方都可以打卡,任一方完成即可
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 任务编辑页可「添加共同执行人」
  - 共同执行人在自己的 app 内也能看到该任务并打卡
  - 任一方打卡即标记为完成,通知双方

**US-010 共享任务仅查看**
- **As a** 任务创建者
- **I want** 把任务分享给配偶「仅查看」
- **So that** 对方能知道但不需要打卡
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 任务可标记为「共享查看」(只读)
  - 共享对象能在家庭看板看到该任务
  - 共享对象无打卡按钮

#### M5 — 家庭公开看板

**US-011 查看家庭公开看板**
- **As a** 家庭成员
- **I want** 看到家庭公开看板
- **So that** 我能概览家庭整体任务进度
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 看板仅显示被标记为「共享」的任务
  - 包含每个家庭成员今日/本周完成情况
  - 双方都能查看

#### M6 — 家庭管理与身份配对

**US-012 创建 / 加入家庭**(v1.1 修订)
- **As a** 用户
- **I want** 创建一个家庭或加入配偶的家庭
- **So that** 我们能一起使用这个 app
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 首次启动自动生成匿名设备 ID(详见 US-013)
  - 创建家庭:在「家庭」页面点击「创建家庭」,系统生成 **6 位邀请码**,**10 分钟内有效**
  - 加入家庭:配偶在「家庭」页面输入邀请码即可
  - 双方在云端配对为同一 family,所有任务数据按 family ID 同步
  - 同一家庭最多 2 个成员(MVP 限制)
  - 邀请码过期后可重新生成
- > 📌 v1.1 修订:补充了匿名身份 + 邀请码配对的具体流程,以及邀请码有效期(10 分钟)。

**US-013 匿名设备身份初始化**(v1.1 新增)
- **As a** 首次使用 app 的用户
- **I want** app 自动给我分配一个匿名身份
- **So that** 我不需要注册账号就能直接使用
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 首次启动自动生成一个 UUID 存于本地
  - 不要求任何个人信息(手机/邮箱/微信/密码)
  - 设备 ID 对用户不可见,仅作为"我是谁"的内部凭证
  - 同一设备上只有一个有效 ID
  - 卸载重装后会生成新 ID(MVP 接受;无恢复机制,见 §6 假设 A6)

#### M7 — 集中设置页面(v1.2 新增)

**US-017 集中设置页面**
- **As a** 用户
- **I want** 有一个集中的「设置」页面
- **So that** 我能调整各项偏好(推送时间、过期窗口、补卡截止等)
- **Priority**: P0
- **Status**: ⚪ Not Started
- **验收标准**:
  - 入口:首页右上角或底部 Tab「我的 → 设置」
  - **推送时间设置**
    - 早汇总时间(默认 08:00)
    - 晚汇总时间(默认 20:00)
    - 时段范围(避免设置到 23:59 这种极端值)
  - **过期提示窗口设置**(对应 US-015)
    - 选项:今+昨(默认)/ 本周(周一~今)/ 全部 / 关闭
  - **补卡截止时间设置**(对应 US-006)
    - 选项:当天 23:59(默认)/ 次日中午 12:00 / 关闭补卡
  - **白名单/自启动**(对应 US-016)
    - 「重新检测」按钮,触发 US-016 引导流程
  - **关于**
    - 版本号
    - 隐私说明(简述匿名 ID 模型)
    - 联系反馈(暂时留邮箱或加 QQ 群入口,见开放问题)
- > 📌 v1.2 新增:把分散在各 story 里的"可配置"项集中到设置页面,避免配置入口散落各处。

## 5. 非功能性需求(仅列出已讨论项)

> 未经显式讨论的 NFR 不在此文档中假设。

| 维度 | 要求 | 备注 |
|---|---|---|
| **目标平台** | Android only(首发) | 由用户在 Phase 1 确认 |

## 6. 约束与假设

### 6.1 约束
- **C1**:MVP 只支持夫妻 2 人,不开放多人/多家庭(产品约束,见 Non-Goals)。
- **C2**:MVP 不发布到任何应用市场,通过 EAS Build 生成 APK 直接安装。
- **C3**:推送使用 Expo Push,免费额度内运行;超出后需评估付费或自建。
- **C4**:家庭试用观察期 2-3 个月,验证 G5 指标后再决定后续。
- **C5**(**v1.1 新增**):**不保证 100% 推送到达**。Android 系统对后台 app 限制严格,即便加白名单仍可能被省电模式/内存压力杀掉。

### 6.2 假设
- **A1**:用户双方都有 Android 手机,且能正常收到 Expo Push 通知。
- **A2**:用户在同一 WiFi 或可联网环境下使用(打卡/同步需要联网)。
- **A3**:用户的家庭事务规模适中(MVP 设计目标:每周 5+ 任务),不假设企业级量。
- **A4**:用户对手机权限(通知、自启动)授予意愿较高(若不授予,推送无法到达)。
- **A5**(**v1.1 新增**):用户愿意按引导把 app 加入电池白名单/自启动,以保证推送可达。
- **A6**(**v1.1 新增**):卸载重装视为新身份(MVP 不做身份恢复);如果发生,需要配偶重新发起邀请码配对。

## 8. 术语表(Glossary)

| 术语 | 释义 |
|---|---|
| 任务(Task) | 用户创建的一个事项,可以是一次性或周期 |
| 周期任务(Recurring Task) | 按一定规则重复的任务(每日/每周/每月/自定义) |
| 打卡(Check-in) | 标记任务完成的动作 |
| 补卡(Makeup Check-in) | 漏打卡后补打过去某一实例 |
| 指派人(Assignee) | 任务的主要执行者 |
| 共同执行人(Co-executor) | 被指派一起完成任务的成员,任一完成即可 |
| 家庭看板(Family Board) | 展示家庭共享任务的视图 |
| 家庭(Family) | 一个 FamSchedule 协作单位,MVP 仅支持 2 人 |
| 邀请码(Invite Code) | 加入家庭时使用的 6 位一次性凭证(有效期 10 分钟) |
| Expo Push | Expo 提供的统一推送服务,覆盖 iOS/Android |
| 匿名设备 ID | 首次启动生成的本地 UUID,作为用户在云端的匿名凭证,无需注册 |
| 白名单/自启动 | 国内 Android 厂商提供的"允许 app 在后台运行"开关,保证推送可达 |
| 过期提示窗口(v1.2) | 启动 banner 显示过期任务的时间范围,默认"今日 + 昨日" |
